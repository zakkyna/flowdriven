Copied from `docs/design/build-order.md` section B-01; that file and the design set it names are the instructions. Approval basis: the owner approved the clickable prototype ("sudah oke", 2026-11-21) and asked for the whole V1 build to start, test first, with no questions before V1 is done.


- Release: V1.
- Goal: Contract version 1 is frozen first (a read-only copy on the `/v1` subpath, with every importer pointed at it by mechanical tasks), so the code that stays on version 1 keeps compiling while the root contract becomes version 2: states, read models, cards, the 45 live operations with their table fields (and the 12 retired entries), the version check, a fixture client that answers every operation, and a dispatcher with a legacy map for the version 1 handlers that stay until their step. Build order inside B-01: T5, T12 to T17 (the freeze), T1 to T4, T6, T9, T8, T18, T10, T7, T11.
- Depends on: B-00.
- Prototype gate: All V1 journeys (j01, j12, j20 to j25, j27 to j31), because the contract fixes every operation, card and state they use. No PU item of its own: nothing is shown to a person, and each PU behaviour the contract carries is approved before the step that builds it.
- Ask first: None.
- Dependency changes: none.
- Security review: Required (approvals). Focus: T-02, T-04, T-05, T-06, T-17. Why: new decision and run states and the person-only operations.
- Chair decisions for every B-01 task (pre-flight, 2026-11-21): read-only scouts checked T1 to T4, T6 to T11 and T18 against the design set and the code, skeptics confirmed 57 of 59 points, and the decisions are written under each task. Three rules hold for all of them:

  - A root test that pins a version 1 shape is rewritten with equally strict version 2 assertions by the task that changes that shape (decision 15); its copy in `v1/` keeps the version 1 assertions. No test is deleted.
